# 工作类目词典

把零散记录归到固定类目，是「不写流水账」的第一步。本词典给出通用类目 + 岗位扩展类目 + 归类规则。

## 一、通用六类（所有岗位通用）

| 类目 | 含义 | 典型动作词 |
|------|------|-----------|
| 业务推进 | 直接产生营收/客户/拓展的结果 | 拜访、报价、成单、拓客、谈判、签约 |
| 项目交付 | 把事做出来、上线、验收 | 开发、实施、上线、验收、交付、测试 |
| 协作沟通 | 对齐、协调、答疑、会议 | 开会、对齐、协调、答疑、评审、同步 |
| 问题解决 | 故障、客诉、风险、复盘 | 修复、定位、复盘、止损、兜底、排查 |
| 能力建设 | 流程/文档/学习/工具沉淀 | 写 SOP、沉淀、学习、搭工具、培训 |
| 管理动作 | 招聘/考核/规划/决策（管理岗） | 招聘、考核、规划、拍板、复盘会 |

## 二、岗位扩展类目

### 研发 / 技术
- 新功能（feature）：新增能力
- 缺陷修复（fix）：bug、报错、异常
- 重构优化（refactor）：性能、结构、技术债
- 文档（docs）：注释、README、接口文档
- 线上事故（incident）：告警、宕机、降级

### 销售 / 业务
- 新客（lead）：拉新、引流、转介绍
- 跟进（follow）：报价、议价、方案
- 成单（deal）：合同、签约
- 回款（cash）：到账、账期
- 丢单（loss）：流失、竞品、放弃

### 运营 / 内容
- 内容产出（content）：写稿、剪辑、排版
- 投放（ads）：投流、买量、SEO
- 互动（engage）：评论、私信、社群
- 转化（convert）：留资、下单、涨粉

### 职能 / 支持
- 处理量（volume）：办理件数、服务人次
- 时效（sla）：平均处理时长、准时率
- 差错（error）：出错率、退回率

## 三、归类规则（冲突时怎么判）

1. 一条记录同时是「动作」和「结果」，归到**结果类目**。例：「开发并上线了 X」→ 项目交付。
2. 会议如果产出决策，归「协作沟通」；如果会议本身就是交付物（如述职会），归对应业务类目。
3. 修复类：凡带「修/定位/排查/解决」且针对已存在问题，归「问题解决」；新写的归「项目交付」。
4. 学习若直接产出可复用物（SOP/脚本），归「能力建设」；纯听课归「能力建设」但标注「待转化」。
5. 实在归不进的，放「其他」并在汇报里单列，别硬塞。

## 四、类目使用禁忌

- 不要每类都写一样多。周报里「业务推进」「项目交付」应占大头，「协作沟通」压到最少。
- 类目是给老板看的导航，不是给你凑字数的。一类里没东西就删掉该类目，别留空标题。
