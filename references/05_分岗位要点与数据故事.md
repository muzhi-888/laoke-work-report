# 分岗位要点与数据故事

## 一、分岗位强调点

| 岗位 | 强调 | 必带数据 | 老板最想看 |
|------|------|---------|-----------|
| 销售/业务 | 漏斗每层、新增丢失、客单价 | 线索/报价/成单/回款/丢单 | 漏斗推进几格、瓶颈层 |
| 研发/技术 | 交付物、稳定性、技术债 | 上线数/修复数/故障率/响应 | 更稳没、按时没、埋雷没 |
| 运营/内容 | 曝光→互动→转化、爆款归因 | 产出/曝光/互动率/涨粉/转化 | 哪类有效、预算值不值 |
| 职能/支持 | 处理量+时效+差错、业务影响 | 件数/SLA/差错率 | 让别的部门少操心啥 |
| 管理 | 目标完成度、人效、风险、决策 | 团队目标%/人效/风险 | 目标偏差、人才风险、拍板事 |

## 二、数据故事四段式

1. 开场定调（一句话核心贡献）
2. 证据支撑（2-3 个最硬数据，别全摊）
3. 转折/卡点（诚实说难处+已解+待解要啥）
4. 收尾指向未来（下周/下月重心）

反例：「成单 12，客单价 9200，跟进 8，会议 5，修复 3……」（无重点）
正例：「主线跑通高客单线：成单 12(+33%) 中 7 单来自新拓高客单线，客单价拉到 9200。卡点报价响应慢，加模板压到 4h。下周复制打法到 3 个老客户。」

## 三、管理岗改写

- 把「我做了」→「团队达成了」
- 个人产出少写，团队产出多写
- 风险段必写人才风险与需拍板项

## 四、职能岗翻译

支持岗成果常「看不见」，主动翻成业务影响：
「招到 3 人」→「填补产线缺口，避免交付延期」
「处理 200 单」→「200/210 在办，准时率 95%，差错率 0.5%」

## 五、时间投入参考

- 有现成记录：出稿 3min + 核 5min = 8min
- 仅碎片：列关键词 10min + 出稿 3min + 核 5min = 18min
- 月报合成（4 周报）：合成 5min + 校验 10min = 15min（比翻聊天快 1h）

## 六、为什么不用通用 AI 瞎写

有骨架（五步法+三类模板）、逼量化（强制带数）、守边界（不编不美化、缺口标待补）、可复核（每步可见）、能自动化（commit 直出）。
