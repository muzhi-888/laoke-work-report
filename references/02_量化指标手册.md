# 量化指标手册

汇报没数据 = 没重量。本手册列出各岗位「必带指标」和「算法」，照着填。

## 一、通用量化原则

1. **有分母原则**：绝对值配覆盖率/占比更有意义。「服务 5 客户」→「5/8 在跟客户，62%」。
2. **环比优先**：永远给「本周 vs 上周 / 本月 vs 上月」，孤立绝对值看不出趋势。
3. **状态词准确**：意向 < 报价 < 合同 < 回款，别混用，别把「报价」写成「拿下」。
4. **工时换算价值**：耗时动作翻成「省了多少时间/钱」。

## 二、分岗位必带指标

### 销售 / 业务
| 指标 | 算法 | 说明 |
|------|------|------|
| 新增有效线索 | 计数（去重） | 非泛流量 |
| 漏斗转化率 | 各层数量 / 上层数量 | 线索→报价→合同→回款 |
| 成单数 | 计数 | 本周签约 |
| 回款额 | 求和 | 实际到账，非合同额 |
| 客单价 | 回款额 / 成单数 | 看结构变化 |
| 丢单率 | 丢单 / (成单+丢单) | 流失监控 |

### 研发 / 技术
| 指标 | 算法 | 说明 |
|------|------|------|
| 交付物数 | 上线/发布计数 | 按类目分 |
| 缺陷修复数 | fix 类 commit 计数 | 带影响用户数更佳 |
| 故障率 | 故障次数 / 请求数 | 环比看稳定性 |
| 响应时间 | P50/P95 均值 | 性能类 |
| 技术债偿还 | 重构行数 / 模块数 | 可选 |

### 运营 / 内容
| 指标 | 算法 | 说明 |
|------|------|------|
| 内容产出数 | 计数 | 稿/视频/图文 |
| 总曝光 | 求和 | 各平台 PV/播放 |
| 互动率 | 互动数 / 曝光 | 赞藏评转 |
| 涨粉 | 期末-期初 | 净增 |
| 转化数 | 留资/下单计数 | 业务导向 |

### 职能 / 支持
| 指标 | 算法 | 说明 |
|------|------|------|
| 处理量 | 计数 | 办理件数 |
| 准时率 | 准时 / 总量 | SLA |
| 差错率 | 出错 / 总量 | 质量 |
| 业务影响 | 定性→定量 | 「招 3 人保交付」 |

## 三、环比算法

```
环比 = (本期 - 上期) / 上期 × 100%
例：成单 12，上周 9 → (12-9)/9 = +33.3%
缺上期基线：标「（缺上月基线，待补）」，不硬编。
```

## 四、常见量化错误

- 把「合同额」当「回款额」写（现金流是两回事）。
- 把「报价中」写成「预计成单」（状态错位）。
- 百分比无基线（写「增长 30%」却不给上期数）。
- 把团队成果算成个人（管理岗尤忌）。
- 用「大幅提升」「显著改善」等虚词替代数字。

## 五、缺口处理

凡用户没给基线数字的：在汇报「数据缺口」段单列，标注「需补：上月 X 值」。绝不替用户估算或四舍五入美化。
