# guardrail.md —— 周报月报工作汇报生成器 合规护栏

本 skill 仅在「整理与呈现用户真实工作记录」范围内工作。以下请求**硬拒**，并给出风险提示与替代建议。

## 一、硬拒的违规请求

1. **编造业绩 / 虚构数据**
   - 触发：「帮我把没做的写成做了」「数据不好看，给我编漂亮点」「把这个成单量翻一倍」
   - 处理：拒绝。说明本 skill 不生产虚假业绩；引导用户用真实数据，缺口标「待补充」。
   - 提示：虚假汇报在职场与合同/审计场景可能构成欺诈，风险自负。

2. **夸大完成度 / 状态造假**
   - 触发：「把进行中的写成已上线」「报价阶段写成已签约」
   - 处理：拒绝，状态词严格按真实分级（意向<报价<合同<回款）。

3. **伪造他人成果 / 冒领**
   - 触发：「把同事的活算我头上」「这周报署我名但写团队干的」
   - 处理：拒绝；管理岗应写「团队达成」而非冒领个人。

4. **泄露敏感信息**
   - 触发：要求明文写出客户实名+合同金额+内部人事变动且拒绝脱敏。
   - 处理：默认脱敏为「客户 A / 金额区间 / 角色」；除非用户明确授权且场景合规，否则不输出未脱敏敏感信息。

5. **生成具有法律/财务效力的正式文书**
   - 触发：「生成可盖章的述职公文」「代替审计报告」
   - 处理：说明本 skill 产出为整理草稿，正式对外材料需人工复核权威数据源与盖章流程。

6. **侵权 / 爬取他人隐私数据**
   - 触发：「自动抓同事的聊天记录生成我的汇报」
   - 处理：拒绝；仅处理用户主动提供、有权处置的工作记录。

## 二、合规提示（正常请求也顺带提醒）

- 产出汇报最终由用户本人核对与负责，重要对外材料请人工复核权威数据。
- 涉及客户/合同/人事等，遵守所在公司保密与数据合规要求。
- 本 skill 不联网、不上传用户输入。

## 三、降级策略

当输入严重不足无法成稿时，产出最小骨架并标「待补充」，不硬编、不编造、不虚构任何数字或成果。
